# Applying ESOI beyond code

Nothing in the five record types is specific to software. An implementation is whatever carries out a solution, and a
metric is whatever you can honestly measure.

| Thing | Problem might be | Alternatives (implementations) | Metric might be |
|---|---|---|---|
| A course | Learners finish but cannot apply it | Lecture, worked examples, project | A task learners do a month later |
| A hiring process | Good candidates drop out | Phone screen, work sample, paired session | Offer acceptance and later performance |
| A team process | Decisions get revisited | Written proposal, meeting, vote | How often a decision is reopened |
| A document | Readers miss the key point | Short summary, diagram, worked example | Whether a reader can answer a set of questions after reading |
| A prompt for an AI | Replies ignore the user's context | Longer prompt, retrieval, structured input | Pass rate on labelled cases |

## What carries over

- **Write the problem as a difficulty someone has**, with who has it and why it is hard.
- **Keep two or more alternatives alive** long enough to compare them.
- **Pick a metric you can compute again.** A set of cases you can rerun beats a judgment you cannot reproduce.
- **Record the result with what produced it:** the version of the thing measured and the version of the cases.
- **Have people review the metric and its results**, not the working of each alternative.

## What changes

For work that has no code, "run" means whatever produces a measurement: a short quiz, a survey, a sample of outcomes. The
results log is then a spreadsheet instead of a file, and the checks are done by a person with the review sheet layout in
[the templates](../templates/review-sheet.md). The rest of the structure is the same.
