# Rules

Generated by `esoi rules --markdown`; each problem line printed by `esoi check` starts with the id of the rule it breaks. Records are checked by rules R1 to R7 inside S26 (R5 is the parent and retired-column check, R6 the authoritative metric of a solution with several, R7 a column the owner has not approved). S28 and S29 apply only to the intent layout, where the configured folder holds a project's top intent (why the project exists, in its own words, never ESOI by default) and each subfolder with its own `intent.csv` is a sub-intent; the evolvable structure a project applies is a solution inside its top intent, whose implementation may use esoi solutions (`uses_solution_ids`, written `@project_id/solution_id` for another project).

- **S1** Every file belongs to exactly one component and every component path glob matches a file; a document named in `documents` is a file of that component and has one owning solution.
- **S2** Every component row has a role and a layer from the configured set.
- **S3** No Python file at the repository root (unless root_python_files is set, the file is listed in root_python_allow, or a waiver names it).
- **S4** No Python module over the size ceiling (max_lines); split by role or waive with a reason.
- **S5** Every module of the package opens with a docstring that states its role.
- **S6** Dependencies point inward: a module imports its own layer or a lower one (TYPE_CHECKING imports ignored).
- **S7** Every Protocol class is in the interface_name cell of some solution; implementation filepaths and metric scripts exist; selected is a listed implementation or a selection-table name.
- **S8** COMPONENTS.md matches components.csv, and each intent folder's README.md and diagram.md match its records (esoi check --write-docs regenerates them).
- **S10** A measured solution's selected implementation has a recorded row and no rival beats it on the metric, or a waiver names the pending decision.
- **S11** Every measured solution is linked from some component, and every linked id exists (a solution with no metric command is a specification, derived, and needs no component).
- **S12** Every evaluation implementation drives live package code or declares itself an alternative (ALTERNATIVE = True, or a docstring opening ALTERNATIVE, ABLATION or VALIDITY); a selected or measured implementation must be live, or waived.
- **S13** A layer (or path prefix) listed in [rules.S13] reads no environment variables; the value is passed in.
- **S14** Every solution with an interface_name has a selection-table entry and no entry lacks a row; a default, when the entry holds one, is one of its implementations and each implementation's module is listed in the row's implementations cell or in the `filepath` of one of its implementations.csv records (several implementations may share a module).
- **S16** The latest results row of every implementation carries a cases_sha, or a waiver says why not.
- **S17** The tracker tabs match what the registry and the results log now produce (only tracking_* columns are hand-edited). Checked when the tracker folder exists.
- **S18** Solution and component ids are unique and no id repeats inside one cell.
- **S19** Every component names at least one solution.
- **S20** Every solution has a problem, an ideal, a metric, implementations, a selected implementation and a recorded run on the current cases with a git_sha (a solution whose metrics record no run is a specification and is not checked here). With --strict a run on code that changed since is advice only (it informs, never fails the check or blocks a commit), and so is a rival it was compared with (waive one rival as `<solution>:<implementation>`).
- **S21** Every evaluation folder is named by some solution's metric command, or is listed as shared.
- **S22** No score, percentage, dollar amount or case count in a waiver reason or a record field (a solution's milestones may state target values); numbers live in the results log.
- **S23** For a solution whose selection-table entry still holds a `default`, selected equals it (an entry with no `default` takes the records' `selected`, so there is nothing to compare).
- **S24** Every arm a metric command names has a results row.
- **S25** A solution whose evaluation folder has a single implementation, so nothing to compare it with, has a broken/ naive module besides __init__.py: the naive implementation a first draft would write, which the cases must fail.
- **S26** The intent records fill every field of the evolvable-structure template and link as it says (a problem is not a task, every problem has a solution and an ideal, links agree both ways), and parent links resolve (in the legacy layout, to the overall network; in the intent layout, anywhere in the tree). A records file carries no other column than the template's fields, technical columns (ids, links, file paths, commands) and the fields the specification's owner approved under `[records] approved_fields` in esoi.toml (R7).
- **S27** The committed template copy equals the source it was parsed from (skipped when the source is not reachable).
- **S28** Each intent folder has one intent.csv row with a unique intent_id and every field of the intent template; the top intent is a root (implements is empty, or names another project's solution as @project_id/solution_id); every intent below it is an implementation of a solution of its parent: a sub-intent is in a folder named by its intent_id, names, in implements, an implementation of its parent intent, that implementation names it back in sub_intent, and the sub-intent states the opportunities that justify it.
- **S29** A record id is used once across the whole tree (also across record types and intents), and every uses_solution_ids entry names a solution somewhere in the tree other than the implementation's own, or is written @project_id/solution_id for a solution of another project (listed in the local ESOI index, not read here).
- **S30** Every solution and implementation declared in the measured code (@solution, @implementation, register) has its solutions.csv row and implementations.csv record, and the record's filepath is the declaring file; `esoi records sync` writes the missing rows.
- **S31** A metric is meaningfully real: no implementation in a metric's evaluation folder declares SIMULATED = True, and no metric record describes its judge or model as scripted, simulated, mocked or a stand-in (or a waiver names why that metric cannot be real).
- **S32** A metric's `cascading_conditionals` is an ordered list of stages (`name [key=value | key=value]` joined by ` > `): known keys and values, unique stage names, a gate or floor on every stage but the last (not on a `public` or `kind=idea` stage, which needs a `scale`), and a metric `expiration` (and the project's `[expiration] default`) that is `never` or a number of days.
- **S33** Where a metric's cascade has counting results, the solution's selected implementation is the one the cascade chooses (the highest result at the latest stage run, unless another scored higher at an earlier shared stage and has not been run there yet), or a waiver names the pending decision (waive as `<solution>`).
- **S34** The template version recorded under `[records] template_version` in `esoi.toml` is the version this library carries (`esoi version`). When the library's is newer, the finding names the fields that changed since and the migration command if one applies; when the record is ahead of the library, the library needs upgrading. Nothing recorded is not a finding.
- **S35** Where `[parent]` names the package this one builds on, a solution whose `selected` arm differs from the parent's default cites in `overrides.csv` (`solution_id`, `reason_ids`) the id of one of its own problem, ideal or metric records, or a waiver names the pending decision (waive as `<solution>`). An `unconfirmed:` reason does not satisfy it.
- **S36** Opt-in network: the top intent's one root solution is the solution the repository implements (a problem, an ideal, an authoritative metric and at least two implementations), every problem, ideal and metric of the top intent links up to it, and each linked record has real text (waive as the record id).
- **S37** Opt-in entry: a solution with code declares @solution(<id>, kind=, entry=, example=) and names it in interface_name; every declared solution and every intent answers its one line offline (python3 -m esoi.runtime.assemble_by_name.entry_cli); the README's first example that calls <package>.run( runs (waive as the solution or intent id, or README.md).
- **S38** Opt-in coherence: every intent passes python3 -m esoi.structure.structure_check.coherence: paragraph both ways, roots, diagram, code precision, coverage and lift at the [rules.S38] floors (per intent), fan-out and depth (waive as the intent id).
- **S39** Opt-in ratchet: the trend of the waiver sets, the enabled rules and the S38 floors and ceilings against a base commit (shown, never a failure).
- **S40** Opt-in by `[records] beside_code` (or `[rules.S40] enabled = true`): a solution's spec row and the code of its implementations are in the same folder or one link apart; a folder that holds an implementation's code has a README.md; a record lives in one place; a reference or registry implementation lists only paths that resolve and every code file that declares the solution (advisory; waive as the solution id, the folder's path, the implementation id or the record id).
- **S41** Advisory: the stages of one metric's cascade are one number at rising fidelity, so the metric's command scores one component; a cascade whose command scores several has a second criterion beside it (waive as the metric id).
- **S42** Advisory: a solution whose several metrics each have recorded results for the same arms ranks them in separate leaderboards; make one metric authoritative and the others case sources of it (waive as the solution id).
- **S44** Advisory: a `[balance.<component>]` table (weights and budgets) was fixed before any alternative was scored, so it did not change in a commit dated after the first row scored with it (waive as the component).
- **S45** Advisory: the arm that scores best on the balanced metric is not degenerate by the diagnostics the metric declares (`[balance.<component>.diagnostics.<column>]` min and max); it informs and never excludes an arm (waive as the component).
- **S46** Advisory: a record's `name` is the human-readable label that leads every generated page, not its handle: a name that is missing, equals its own id (or the arm part of it), is the id with a suffix or after a colon, or is written kebab-case or snake_case is informed, for intents, solutions, implementations, metrics, ideals, problems and components (waive as the record id).
- **S47** A metric that builds on a foundation (`[builds_on.<component>.<name>]`) declares a readable foundation and shares below 1, every `inherits=` stage exists in the foundation's cascade, and its gates (a stage's gate or floor, the `source_access` read limits) are the same or tighter than the foundation's, never looser (waive as the consumer component).
- **S48** Advisory role scoping: a solution with siblings states what it is not responsible for (out_of_scope) and who owns that (`delegates_to` or a named sibling; `none` says nothing is delegated), two siblings do not overlap strongly in purpose and description, and a container names the `change_driver` that moves its metric (waive as the solution id, or a+b for a pair).
- **S49** Advisory review prompt: a solution with three or more implementations whose descriptions share little is read for one purpose and one level of specificity (a solution holds alternatives of the same job); a prompt, never a verdict (waive as the solution id).
- **S50** Opt-in flow first (advisory): every solution the records say is used has a caller in the code (an import, a typed need or a name in the code of a solution that uses it), and every stated edge is called; informs where the flow is not written yet (code is read; the principle is general) (waive as the solution id, or intent id:solution id for an edge).
- **S51** Advisory: a problem says what is true. An absolute in a problem's text (never, nobody, no one, always, everyone, none, nothing, impossible, the only way, every time, all of) is informed with the words around it, asking whether it is literally true and, if not, what is missing, for whom, how often and at what cost; ideals are not read, since an ideal states the limit state (waive as the problem id, or problem_id:field when the absolute is true).
- **S52** Advisory: an ideal states the state that is wanted, not a solution. Ideal text that opens with an instruction to build or use something (use, build, add, implement, have a, keep a) or that names the means (a method such as 'by comparing' or 'is chosen', one component such as 'one intake' or 'one engine', or a mechanism such as configuration or adapters) is informed, asking what is true for the people or system affected when the ideal is reached (waive as the ideal id, or ideal_id:field).
- **S53** Advisory adoption: a reference `adopts` or `specializes` (`@library/solution_id`, library named in `[adopts.<library>]`) resolves to a solution of a readable library; an adopted row holds no description, purpose, approach, scope, milestones, problems, ideals or role of its own (it does take the application's own arms, metrics, ports and components, and its id resolves like any solution's); an own solution does not say the same job as a library solution; an arm under an adopted solution declares the library's solution id (waive as the local solution id, or own+@library/solution_id for one overlap).
- **S54** Opt-in advisory, Structure Quality scope: every arm defines the methods of its solution's Protocol, a folder declares no more Protocols than its budget, and the arms of one solution share one purpose (waive as the path, unit or solution id a finding opens with).
- **S55** Opt-in advisory, Structure Quality size and cohesion: functions, modules, folders, intents and depth stay inside their budgets (waive as the path or folder a finding opens with).
- **S56** Opt-in advisory, Structure Quality coupling: a unit is called through its entry point, units form no import cycle, and a library names no consumer the project declares (waive as the path or unit a finding opens with).
- **S57** Opt-in advisory, Structure Quality reuse: code copied between files stays under the duplication budget (waive as the path a finding opens with).
- **S58** Opt-in advisory, Structure Quality public surface: a unit exports names that other units use (waive as the unit a finding opens with).
- **S59** Opt-in advisory, Structure Quality behavior preserved: a solution with several arms has a contract test or shared cases that run every arm (waive as the solution id a finding opens with).
